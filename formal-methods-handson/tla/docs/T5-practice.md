# T5. 状態爆発と実務のコツ・次の一歩

## 1. 状態爆発

TLC は到達可能な状態を全部列挙するため、プロセス数やデータ範囲を増やすと状態数が指数的に増えます。

実験(`Mutex.tla`):

```bash
# cfg の Procs を {p1, p2}, {p1, p2, p3}, {p1, p2, p3, p4} と変えて "distinct states" を比べる
tlc -config Mutex.cfg Mutex.tla
```

対策(効く順の目安):

| 対策 | 内容 |
|---|---|
| **モデルを小さくする** | 定数を小さく(プロセス 2〜3、値 2〜3 種)。多くのバグは小さなモデルで出る |
| **抽象化する** | 関係のない詳細を落とす。「バグの本質」だけ残す |
| **対称性削減** | プロセスを入れ替えても同じ状態を 1 つとして数える |
| **並列化** | `-workers auto` |
| **制約をかける** | `CONSTRAINT` で探索範囲を切る(例: メッセージ数 ≤ 3)。ただし網羅性は落ちる |
| **シミュレーション** | `-simulate` でランダムに実行(網羅はしないがバグ探しには有効) |

### 対称性の例

`Mutex.tla` の末尾に `Perms == Permutations(Procs)` を定義済みです。cfg に追加:

```
SYMMETRY Perms
```

`p1` と `p2` を入れ替えただけの状態が 1 つにまとまり、状態数が減ります(`Procs` が 3 以上で効果が大きい)。

> [!WARNING]
> `SYMMETRY` を使うときは **活性(`PROPERTY`)の検査と併用しない**(正しく検査されないことがある)。
> 対称性削減は安全性の検査用と覚えてください。

## 2. TLC の便利なオプション

```bash
tlc -workers auto -config Mutex.cfg Mutex.tla    # 並列化
tlc -deadlock -config X.cfg X.tla                # デッドロック検出を無効化(意図的に止まる仕様)
tlc -simulate -depth 100 -config X.cfg X.tla     # ランダムシミュレーション
tlc -coverage 1 -config X.cfg X.tla              # アクションの実行回数(実行されていないアクション = 仕様の誤り)
```

> [!TIP]
> **`-coverage` で「一度も実行されていないアクション」を探す**習慣をつけましょう。
> ガードを書き間違えて「永遠に実行できないアクション」になっていると、不変条件は **空虚に成立** してしまいます
> (何も起きないので破れようがない)。「検査が通った」だけでは安心できない理由です。

## 3. 良い仕様の書き方

1. **まず TypeOK** を書く。仕様の変数の意味が固まる。
2. 不変条件は **小さく複数** に分ける(失敗時の特定が容易)。
3. **バグを仕込んで検出できるか** を確認する(T2 の Buggy 版のように)。検出できない検査は信用できない。
4. 活性は **公平性の仮定を明示** する。
5. 仕様は **設計の議論の道具**。実装の詳細ではなく「決めるべき設計判断」を書く。

## 4. TLA+ の周辺ツール(次の一歩)

| ツール | 内容 |
|---|---|
| **TLA+ Toolbox / VS Code 拡張** | GUI・トレース探索・実行 |
| **TLAPS** | TLA+ の **証明系**。無限モデルについて機械検査つきで証明する(Lean に近い世界)|
| **Apalache** | SMT ベースの **シンボリックモデルチェッカー**。TLC が苦手な大きな整数範囲に強い |
| **Trace validation** | 実装のログが仕様に沿っているか検査する(実装との接続) |

> [!NOTE]
> 学習の次の一歩としては、公式の *Learn TLA+*(Hillel Wayne)や Leslie Lamport の *Specifying Systems* /
> TLA+ Video Course が定番です。題材は「2 相コミット」「Paxos」「分散キュー」などが良い練習になります。

## 5. 他の 2 ツールとの対比(中間まとめ)

| 観点 | TLA+ (TLC) | Lean | Alloy |
|---|---|---|---|
| 反例 | トレース(手順)が出る | 出ない | インスタンス(図)が出る |
| 時間(遷移の順序) | 言語の中心 | 自前でモデル化 | Alloy 6 で可 |
| 保証の範囲 | 有限モデルの網羅 | すべての入力 | スコープ内の網羅 |
| 活性・公平性 | 言語に組み込み | 自前 | Alloy 6 で可(弱め) |
