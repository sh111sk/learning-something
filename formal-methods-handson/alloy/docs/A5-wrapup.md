# A5. まとめ演習と Alloy の限界

## 1. 総合演習: 「会議室予約システム」を自分でモデル化する

ここまでの技術を総動員します(解答は付けません。自分のモデルを検査して確かめるのが目的です)。

### 要件

- `Room`, `Person`, `Booking`(誰が・どの部屋を・どの時間帯で予約するか)。
- 時間帯は `sig Slot` で離散的に(`util/ordering` で順序付けしてもよい)。
- 制約:
  1. 同じ部屋の同じ時間帯に 2 つの予約が入らない。
  2. 1 人が同じ時間帯に 2 部屋を予約できない。
  3. 予約者は予約をキャンセルできる(操作を Alloy 6 の `var` で書く or `State` を sig にする古典スタイル)。

### 課題

1. 上の制約を `fact` として書き、`run` で具体例を数個眺める(想定外の世界は無い?)。
2. 「ある人が予約した部屋は、その人が必ず使える」を `check` する。
3. `book` と `cancel` の 2 操作を書き、**不変条件(制約 1 と 2)が操作で保たれるか** を検査する。
4. わざと事前条件を 1 つ抜いて、反例が出ることを確認する。
5. **スコープを変えて** 結果がどう変わるか確認する。

## 2. Alloy の限界

| 限界 | 内容 |
|---|---|
| スコープ内のみの保証 | 反例なしは、そのスコープでのみ。「全ての場合」の保証ではない |
| 整数が苦手 | 有限ビット幅で回り込む。大きな整数・実数・文字列の計算には不向き |
| 大規模な状態遷移系は苦手 | ステップ数・原子数が増えると SAT が重くなる |
| 活性・公平性の記述は自前 | TLA+ のような `WF` / `SF` は無い |
| 再帰・帰納的定義が弱い | リスト反転のような再帰関数は「関係」として書く(compare で体験) |
| 実行できない | モデルを動かして試す、はできない(実装と切り離された設計モデル) |

## 3. Alloy が最も輝く場面

| 場面 | 理由 |
|---|---|
| **構造・関係の制約** | `join` と閉包で簡潔。ファイルシステム・権限・依存関係・ネットワークトポロジ |
| **設計の初期段階** | 数十行のモデルで「この制約でいいのか?」を数分で確かめられる |
| **反例から学ぶ** | 想定外の世界を図で見せてくれる。要件・ルールの矛盾や抜けを発見 |
| **ドキュメント代わり** | データモデルの意図(制約)を実行可能な形で残せる |

## 4. 他の 2 ツールとの対比(中間まとめ)

| 観点 | Alloy | TLA+ | Lean |
|---|---|---|---|
| 得意 | 構造・関係・ルールの矛盾探し | 並行・分散アルゴリズムの設計 | 関数・アルゴリズムの完全な証明 |
| 保証 | スコープ内の網羅 | 有限モデルの網羅 | 全入力(無限も)|
| 反例 | 図(インスタンス) | トレース | なし(自分で探す)|
| 習得コスト | 低 | 中 | 高 |

→ 次は `compare/` で、**同じ題材を 3 ツールで書き比べ** ます。
