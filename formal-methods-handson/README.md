# 形式手法ハンズオン: Lean 4 / TLA+ / Alloy 6

「形式証明系」の代表的な 3 つのツールを、それぞれ **ゼロから** 手を動かして学び、
**何が得意で何が苦手か** を同じ題材で比較して腹落ちさせるためのコースです。

> [!NOTE]
> 依頼文の「ATL+」は **TLA+**(Leslie Lamport の時相論理による仕様記述言語 / TLC モデルチェッカー)として作成しています。

> [!WARNING]
> **動作確認について**: この教材のコード(`.lean` / `.tla` / `.cfg` / `.als`)は、作成した環境で
> ツールを実行できなかったため、**実機での検証をしていません**。慎重に書いてありますが、
> バージョン差などでエラーになる箇所があるかもしれません。その場合は
> 「エラーメッセージを読んで直す」こと自体が学習になります。直し方が分からなければ
> エラーメッセージを添えて Claude に聞いてください。各ドキュメントの「期待される出力」も
> 実行結果ではなく **予想** です(文言は細部が違う可能性があります)。

## 3 つのツールを一言でいうと

| ツール | 一言 | 検証のしかた |
|---|---|---|
| **Lean 4** | 定理証明器 + プログラミング言語 | 人間が証明を書き、カーネルが機械検査する(**すべての入力**について保証) |
| **TLA+** | 並行・分散システムの設計仕様言語 | TLC が到達可能な全状態を **網羅探索**(有限モデル。反例トレースが出る) |
| **Alloy 6** | 軽量な構造・関係モデリング | 小さなスコープ内を SAT ソルバで **網羅探索**(反例/具体例が自動で出る) |

## 対象読者と前提

- プログラマ。形式手法・論理学の予備知識は不要(必要な概念はその都度説明)。
- Haskell 等の型付き関数型言語の経験があれば Lean の導入は楽(必須ではない)。
- 目標: 各ツールで **小さな題材を自分で検証できる** ところまで + **使い分けの判断軸** を持つこと。

## 進め方(推奨)

1. `docs/00-setup.md` で 3 ツールを入れる(30〜60 分)。
2. `docs/01-big-picture.md` で全体像をつかむ(15 分)。
3. 3 コースを **Alloy → TLA+ → Lean** の順に進めるのがおすすめ
   (フィードバックが速く概念が軽い順。コース同士は独立なので、気になる順でも可)。
4. 3 コースを終えたら `compare/` で同じ題材を並べて比較し、使い分けを固める。

| コース | 目安時間 | 到達点 |
|---|---|---|
| Alloy(A1〜A5) | 約 4〜5 時間 | 構造・関係モデルを書いて反例を読める。Alloy 6 で相互排他を検査できる |
| TLA+(T1〜T5) | 約 5〜6 時間 | 並行アルゴリズムを仕様化し、TLC で安全性・活性を検査し、バグを見つけられる |
| Lean(L1〜L5) | 約 6〜8 時間 | 帰納法でリスト関数・状態遷移系の性質を証明できる |
| 比較(4 題材) | 約 2〜3 時間 | 3 ツールの得意不得意を、自分の言葉で説明できる |

## 共通題材(比較パートで 3 ツール全てで書く)

1. ロック/相互排他プロトコル(2 プロセスの test-and-set)
2. リスト反転(純粋関数)
3. ファイルシステム/権限モデル(関係モデル)
4. 銀行口座の送金(不変条件と整数演算)
